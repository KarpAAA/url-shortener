# 0003 — Layered module with a framework-free domain; what was deliberately left out

Date: 2026-10-01 Status: accepted

## Context

The author's NestJS conventions choose architecture per module along three axes — folder
split, domain level (1 anemic … 4 ports), read/write separation — and fix a frame that never
varies: module boundaries, a shared error/logging/validation pipeline, transport wired
separately from the core. They are written for systems with users, queues and several
processes. This service has one concept (a link), no users and nothing asynchronous. The
question is which parts of the conventions carry their weight here.

The conventions' own test for every layer: _what specific change does this protect me from,
and will that change actually come?_

## Options considered

- **Level 1** — a controller, a service with Prisma calls, a DTO. Three files. Honest for a
  key–value store, but the service _has_ rules that can be violated by bad data (which URLs
  are acceptable, what a code is, which words are reserved, how collisions are handled), and
  the brief asks for edge cases to be handled and tested.
- **Level 3** — domain + concrete repository, no ports. Use cases can then only be tested
  through a real database.
- **Level 4** — ports for the repository and the code generator, with fakes.

## Decision

One business module, `links`: **layered · level 4 · CQS**.

- `domain/` is plain TypeScript and imports no package at all. `OriginalUrl` and `ShortCode`
  are value objects that cannot exist in an invalid state.
- `application/` holds two use cases that depend on ports (`LinkRepository`,
  `CodeGenerator`) and on `Clock`.
- `read/` is a separate query service: it reads through the ORM with an explicit `select`
  and returns DTOs.
- The core module is inert; `links.http.module.ts` declares the controller.
- Boundaries are lint rules, and each rule has a test that proves it fires.

**Applied from the conventions as written:** structure and naming, validated configuration,
the error hierarchy and single filter, structured logging with a correlation id, UUID v7 keys
generated by the application, migrations as a separate deploy step, DTOs at every edge, the
four test layers, Conventional Commits and hooks.

**Deliberately not applied**, each with the trigger that would bring it back
(the list is also in `.claude/rules/project/deviations.md`):

| Convention                                                | Here                                                                              | Why                                                                                                                                  | Comes back when                                    |
| --------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| `Actor` on every use case; policies; guards               | none                                                                              | no authentication; an always-allow policy is code without a rule                                                                     | the first endpoint needs an identity               |
| repository ports are rare; no fake for them               | `LinkRepository` port + in-memory fake                                            | collision retries and the round-trip property are tested in milliseconds, and mutation testing of `application/` runs without Docker | —                                                  |
| use case returns `void`; repository is `getById` + `save` | `ResolveLinkService` returns the URL; repository is `insert` + `registerVisit`    | load → mutate → save is a read-modify-write that loses visits ([0006](0006-atomic-visit-counter.md))                                 | —                                                  |
| `/v1` prefix, plural nouns, UUID path ids                 | `/shorten`, `/:code`, `/stats/:code`                                              | the brief fixes the paths; a short link must be short                                                                                | a breaking API change                              |
| `api` + `worker` processes                                | `api` only                                                                        | no queue, no cron, no outbox                                                                                                         | the first asynchronous job                         |
| transactions (CLS), outbox, event bus                     | none                                                                              | every write is one statement; there are no side effects to decouple                                                                  | a second write per operation                       |
| hot counters in Redis                                     | counter in PostgreSQL                                                             | exact counts, no Redis in scope                                                                                                      | hot-row contention ([`scaling.md`](../scaling.md)) |
| throttler with Redis storage                              | in-memory                                                                         | one instance ([0010](0010-rate-limiting.md))                                                                                         | the second replica                                 |
| metrics, tracing, alert rules                             | logs + health                                                                     | out of scope; described in [`scaling.md`](../scaling.md)                                                                             | the first SLO                                      |
| Swagger off in production                                 | always on                                                                         | the contract is public and is what the fuzzer reads                                                                                  | an internal deployment                             |
| error shape `{code, message, details}`                    | RFC 9457 with the same fields as extensions                                       | the brief asks for it ([0009](0009-error-format-rfc9457.md))                                                                         | —                                                  |
| a facade as the module's only export                      | use cases and the query service are exported to the module's own transport module | there is no second module; an empty wrapper is noise                                                                                 | a second module                                    |
| errors documented once, globally                          | per endpoint                                                                      | the fuzzer checks each endpoint's statuses against the schema                                                                        | —                                                  |

## Consequences

- About thirty small source files for three endpoints. That is the price of rules that are
  unit-tested without a framework and boundaries that cannot erode silently — and it is the
  thing the brief asks to see.
- The domain is trivially testable: 149 mutants in `domain/` and `application/`, none survive.
- The repository port exists for a test double, not for a second database. That is a
  conscious deviation from "no port in case we swap the DB"; the fake is kept honest by
  running through the same contract tests as the Prisma adapter.
- Everything left out is one module, one process or one dependency away, and nothing built
  now has to be undone to add it.
