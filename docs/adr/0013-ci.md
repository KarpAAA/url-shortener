# 0013 — Continuous integration

Date: 2026-10-01 Status: accepted

## Context

Every check that exists locally — lint, types, five kinds of tests, migrations, the contract,
commit messages — is only a rule if something enforces it. Git hooks can be skipped
(`--no-verify`, a commit from an IDE); CI cannot. The checks differ a lot in cost: lint takes
seconds, mutation testing minutes.

## Options considered

- **One job running everything in sequence.** Simple; slow feedback, and a lint error is
  reported after the container tests.
- **Jobs by cost, cheapest first**, with the expensive suites fanned out behind the cheap
  gate.
- **Mutation and fuzzing on every pull request**: the most signal, minutes per push.
  **Only on the main branch and nightly**: the conventions' choice.

## Decision

GitHub Actions, `.github/workflows/ci.yml`, on pushes to `master`, pull requests, a nightly
schedule and manual dispatch.

| Job           | Runs                              | Steps                                                                                                                                                                                           |
| ------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `quality`     | always                            | lint → format check → typecheck → architecture tests → unit and property tests → build → `docs/openapi.json` and `docs/traceability.md` are up to date → `pnpm audit --prod --audit-level=high` |
| `integration` | after `quality`                   | integration and API tests (Testcontainers)                                                                                                                                                      |
| `migrations`  | after `quality`                   | every migration applied to an empty PostgreSQL service, then `prisma migrate diff --exit-code` against the schema                                                                               |
| `commits`     | push, pull request                | commitlint over the pushed commits: Conventional Commits, header ≤ 72, no AI attribution trailers                                                                                               |
| `contract`    | push to `master`, nightly, manual | Schemathesis through the Compose override                                                                                                                                                       |
| `mutation`    | push to `master`, nightly, manual | Stryker; score in the job summary, HTML report as an artifact                                                                                                                                   |

- pnpm's store is cached by `actions/setup-node`; installs use `--frozen-lockfile`.
- `concurrency` cancels a superseded run of the same ref.
- `HUSKY=0`: hooks are a local shortcut; CI repeats every check a hook runs.
- The workflow's token is read-only.
- Dependabot opens weekly updates for npm (minor and patch grouped), Docker, Compose and
  Actions. Majors that need a deliberate migration are ignored with the reason in the file
  ([0001](0001-language-framework-package-manager.md)).

## Consequences

- A lint error fails in under a minute; container suites run only after the cheap gate passes.
- The migration check is its own visible job, although an integration test covers the same
  ground — schema drift is the kind of failure that should have its own name in the run.
- A committed `docs/openapi.json` that CI keeps in sync makes any contract change a diff in
  review.
- Mutation and fuzz results arrive after a merge to `master`, not before. With a single
  author pushing to `master` that is the same moment; with pull requests they would move to
  a required check once their duration is known.
- The audit gate blocks on `high` in production dependencies only; lower and dev-only
  advisories are triaged from Dependabot alerts.
